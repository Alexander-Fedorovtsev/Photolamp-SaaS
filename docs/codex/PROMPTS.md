# PROMPTS для Codex

## Prompt 1 — старт проекта

Изучи следующие документы в репозитории:
- `docs/architecture/saas-tz.md`
- `docs/product/landing-page-spec.md`
- `docs/product/brand-messaging.md`
- `docs/codex/CODEX_BRIEF.md`
- `docs/codex/IMPLEMENTATION_PLAN.md`

Затем:
1. кратко зафиксируй архитектуру проекта;
2. предложи структуру репозитория;
3. реализуй foundation для frontend и backend;
4. добавь инструкции локального запуска;
5. подготовь изменения как первый PR.

Важно:
- проект должен быть multi-tenant с первого коммита;
- MVP не должен использовать избыточные микросервисы;
- основная цель — подготовить продающий сервис аренды фотоламп и будущую SaaS-платформу для других арендодателей.

---

## Prompt 2 — реализовать landing page

Опираясь на:
- `docs/product/landing-page-spec.md`
- `docs/product/brand-messaging.md`

реализуй продающую главную страницу.

Нужно:
- mobile-first layout;
- hero с мягкой анимацией;
- CTA “Оформить аренду” и “Заказать по телефону”;
- блок “Как это работает”;
- преимущества;
- калькулятор стоимости как UI-компонент;
- FAQ;
- bottom CTA;
- адаптивность и доступность.

Используй современный, тёплый, дружелюбный стиль. Не используй агрессивную медицинскую рекламу и не делай заявлений о гарантированном выздоровлении.

## Prompt 3 — multi-tenant foundation

На основе `docs/architecture/saas-tz.md` реализуй основу multi-tenant backend:
- users;
- tenants;
- memberships;
- tenant-scoped authorization;
- подготовь миграции;
- зафиксируй подход к PostgreSQL RLS;
- добавь тесты на tenant isolation.

Подготовь PR с кратким описанием модели безопасности.

---

## Prompt 4 — онлайн-заказ

Реализуй пользовательский сценарий онлайн-заказа:
- availability;
- quote;
- hold;
- order creation;
- кабинет клиента.

Требования:
- сервер пересчитывает стоимость;
- нельзя забронировать один asset дважды;
- телефон пользователя подтверждается через OTP;
- UI должен оставаться простым и mobile-first.

---

## Prompt 5 — заказ по телефону

Реализуй обязательный сценарий оформления заказа оператором по телефону.

Нужно:
- административная форма “Новый заказ по телефону”;
- поиск/создание клиента внутри tenant;
- использование той же availability логики, что и для онлайн-заказа;
- отправка SMS клиенту со ссылкой на вход в личный кабинет;
- сохранение source=`phone` и created_by_staff_user_id.

Это не дополнительная функция, а один из основных сценариев продукта.
