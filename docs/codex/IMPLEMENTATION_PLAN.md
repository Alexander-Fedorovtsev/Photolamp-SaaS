# IMPLEMENTATION_PLAN

## Общий принцип

Реализовывать проект поэтапно, небольшими PR, сохраняя рабочее состояние репозитория.

---

## Этап 0. Repo foundation

### Цель
Подготовить базовую структуру монорепозитория или согласованной структуры frontend/backend.

### Что сделать
- создать frontend app;
- создать backend app;
- добавить docs;
- добавить `.editorconfig`, `.gitignore`, базовые linters/formatters;
- настроить docker-compose для локального запуска;
- добавить README с инструкцией запуска.

### Критерии приёмки
- проект поднимается локально;
- есть базовые health endpoints;
- есть CI для lint/test/build.

---

## Этап 1. Продающая landing page

### Цель
Сделать полноценную конверсионную главную страницу.

### Что сделать
- реализовать header, hero, CTA;
- добавить иллюстративную/анимированную hero-сцену;
- сделать блоки преимуществ, how-it-works, FAQ, bottom CTA;
- сделать калькулятор стоимости как UI-блок;
- реализовать mobile-first вёрстку;
- добавить scroll animations и reduced motion support.

### Критерии приёмки
- страница выглядит как готовый коммерческий продукт;
- есть CTA на оформление и звонок;
- Lighthouse/perf не деградирует критически;
- адаптивность корректна.

## Этап 2. Tenant foundation + auth

### Цель
Сделать основу multi-tenant системы и SMS-авторизации.

### Что сделать
- tenants, users, memberships;
- базовая RLS-стратегия;
- auth by OTP;

### Критерии приёмки

- можно войти по номеру телефона;
- доступ к данным ограничен tenant-границей.

- модели оборудования;

## Этап 4. Онлайн-заказ

### Цель
Реализовать основной сценарий самостоятельного заказа через сайт.

### Что сделать
- availability API;
- quote API;
- hold logic;
- order creation;
- личный кабинет клиента с просмотром заказа.

### Критерии приёмки
- пользователь может оформить заказ онлайн;
- стоимость считается сервером;
- нельзя забронировать один asset дважды.

---

## Этап 5. Заказ по телефону

### Цель
Реализовать административное оформление заказа оператором.

### Что сделать
- UI “Новый заказ по телефону”;
- поиск клиента по номеру телефона внутри tenant;
- оформление заказа оператором;
- отправка SMS со ссылкой на вход/заказ.

### Критерии приёмки
- оператор может оформить заказ целиком без участия клиента в интерфейсе;
- клиент потом может увидеть этот заказ в личном кабинете.

### Текущее состояние

Backend-основа операционной работы с заказом готова: неизменяемый снимок,
tenant-scoped очередь, атомарные подтверждение/отмена и аудит с idempotency key.
Подключение реального SMS-провайдера отложено, но порт и fail-closed заглушка
сохранены. Следующая часть этапа — создание заказа оператором по телефону и
административный UI; отправка SMS остаётся отдельным поздним адаптером.

## Этап 6. Исполнение заказа

### Цель

### Что сделать
